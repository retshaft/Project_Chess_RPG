# GLM 작업 큐

> 2026-09-08 회의 후 범위·우선순위는 [개발 명령서](DEVELOPMENT_ORDERS.md)를 우선한다. 제안 16은 보류, 18은 조사 전용이다. 아래 목록은 기존 참고 자료이며 새 작업의 자동 실행 지시가 아니다. 개별 Ready 작업서 없이 구현을 시작하지 않는다.

기준일: 2026-09-08

GLM-5.3-Flash에 작업을 배정할 때 사용하는 우선순위 목록이다. `[병렬]`은 허용 파일이 겹치지 않아 동시에 실행할 수 있는 작업이고, `[순차]`는 선행 검토 또는 사용자·메인 검증이 끝난 뒤 실행한다. Unity Editor/Test Runner/Play Mode는 한 프로젝트에서 동시에 실행하지 않는다.

모든 GLM 작업은 ZCode 세션 목표(`--target`, 대화형 `/goal`과 같은 역할)를 사용한다. 목표는 "작업서 확인 → 기존 구현 조사 → 필요한 수정 → 자체 점검 → 인계서 작성"을 끝까지 수행하도록 작성하고, 계획만 제시한 채 멈추지 않게 한다. 기본 실행은 `--max-turns 24`, 장시간 작업은 48턴으로 지정한다. 실제 권한·파일 범위·컴파일 차단이 발생했을 때만 중단하며, 시간 초과나 실패를 자동 재시도하지 않는다.

작업 JSON에는 다음 필드를 추가한다.

```json
{
  "goal": "이 작업을 조사·구현·자체 점검·인계까지 완료하세요. 계획만 남기고 멈추지 말고, 실제 차단 사유가 있을 때만 중단하세요."
}
```

## 먼저 지켜야 할 게이트

- M2 대표 넉백/Splat 도구와 M3 상태 회귀 테스트는 현재 `Review`다. 메인이 Unity에서 컴파일·테스트·Play Mode를 확인하기 전에는 M4 이후의 런타임 기능을 추가하지 않는다.
- 기존 적 UnitData 8개 미커밋 변경은 모든 작업에서 보존하며 수정하지 않는다.
- `BattleManager.cs`, `ActionRuntimeController.cs`, 공용 인터페이스, `.asmdef`, 씬·프리팹은 작업서에서 명시적으로 허용하지 않는 한 편집하지 않는다.
- 모든 작업은 새 워크트리에서 시작하고, 허용 파일 밖의 변경이 발견되면 구현을 중단하고 인계서에 기록한다.

## 즉시 배정할 조사·설계 작업

### GLM-01 — M3 상태 조합 설계 감사 `[병렬]

**목적:** 현재 구현과 GDD를 대조해 시연용 상태 조합 2~3개와 확정이 필요한 수치를 제안한다.

**허용 파일:**

- `Docs/Parallel/Tasks/m3-status-package-spec.md`
- `Docs/Parallel/Handoffs/m3-status-package-spec.md`

**명령:**

> `StatusEffectComponent`, EffectSystem 프로세서, 기존 회귀 테스트와 GDD를 읽어라. Chill/Freeze, Stagger/Grab, Bleed 또는 Superconduct 후보의 현재 구현·미구현·충돌 지점을 표로 정리하라. 지속시간, 스택, 갱신, 제거, 행동 제한, 인터럽트, 피해 수치 중 코드가 이미 보장하는 값과 기획 결정이 필요한 값을 분리하라. 코드는 수정하지 말고 위 두 문서만 작성하라. 새 규칙을 임의로 확정하지 말라.

### GLM-02 — M4 대표 인카운터 구조 감사 `[병렬]

**목적:** 기존 AI·예측·팀 커맨더를 변경하지 않고 대표 인카운터를 구성할 수 있는 최소 셋업 범위를 찾는다.

**허용 파일:**

- `Docs/Parallel/Tasks/m4-encounter-audit.md`
- `Docs/Parallel/Handoffs/m4-encounter-audit.md`

**명령:**

> AI 후보 평가, 위험 회피, 팀 커맨더, 예측 경로와 기존 에디터 셋업 도구를 먼저 읽어라. 대표 전투 1개를 재현하기 위해 필요한 유닛 수·배치·행동 순서·승리 조건을 제안하되, 현재 공개 API로 가능한 것과 코어 수정이 필요한 것을 분리하라. 랜덤성 제거 방법과 예측-실측 확인 지점을 포함하라. 코드는 수정하지 말고 허용된 두 문서만 작성하라.

### GLM-03 — M5 아웃게임 흐름 감사 `[병렬]

**목적:** 덱·스테이지·전투·보상·저장·복귀 흐름에서 검증해야 할 연결 지점을 고정한다.

**허용 파일:**

- `Docs/Parallel/Tasks/m5-outgame-flow-audit.md`
- `Docs/Parallel/Handoffs/m5-outgame-flow-audit.md`

**명령:**

> OutgameScene, 덱 빌더, StageSelect, BattleResult, 저장 및 BattleScene 진입 코드를 읽어라. 사용자가 10분 안에 확인할 수 있는 정식 흐름 체크리스트를 작성하고, 덱·칙령·공명 중 실제 전투 수치에 연결된 항목과 연결되지 않은 항목을 구분하라. 씬이나 코드는 수정하지 말고 허용된 두 문서만 작성하라.

### GLM-04 — M6 회귀·로그 정리 계획 `[병렬]

**목적:** 안정화 단계에서 필요한 자동·수동 회귀 항목과 로그 정리 후보를 목록화한다.

**허용 파일:**

- `Docs/Parallel/Tasks/m6-stabilization-plan.md`
- `Docs/Parallel/Handoffs/m6-stabilization-plan.md`

**명령:**

> 기존 EditMode 테스트, DEV_PROCESS 체크리스트, 핵심 런타임 로그 호출을 읽어 전투 시작·AP·이동·점유·넉백·상태·저장·복귀를 검증하는 최소 회귀 세트를 제안하라. 로그 제거가 안전한 항목과 반드시 남겨야 할 진단 로그를 구분하라. 코드는 수정하지 말고 허용된 두 문서만 작성하라.

## 선행 검증 후 배정할 구현 작업

### GLM-05 — M3 상태 패키지 구현 `[순차]`

GLM-01의 설계가 메인과 사용자에게 승인된 뒤 배정한다.

**파일 소유:** 승인된 상태 프로세서·상태 컴포넌트·회귀 테스트 파일만 작업서에 명시한다. `BattleManager.cs`, `ActionRuntimeController.cs`, 씬·프리팹은 금지한다.

**명령:**

> 승인된 상태 조합과 수치만 구현하라. 기존 EffectSystem과 StatusEffectComponent 경로를 재사용하고 중복 틱·중복 상태 저장소를 만들지 말라. 공개 API로 검증 가능한 규칙마다 의미 있는 EditMode 회귀 테스트를 추가하라. Unity Test Runner와 기존 29개 테스트를 실행할 수 없으면 성공으로 표시하지 말고 인계서에 남겨라.

### GLM-06 — M3 상태 가독성 UI `[순차]`

GLM-05의 최종 상태 이름·아이콘·행동 제한 규칙이 확정된 뒤 배정한다. UI 파일만 소유하며 상태 코어 파일은 수정하지 않는다.

**명령:**

> 확정된 핵심 상태 2~3개가 아이콘, 남은 시간/중첩, 행동 불가 이유로 즉시 읽히도록 기존 UI·이벤트 경로를 확장하라. 매 프레임 폴링과 새 런타임 저장소를 만들지 말고 기존 이벤트를 사용하라. 씬·프리팹을 직접 수정하지 말고 필요한 셋업은 별도 에디터 메뉴로 분리하라.

### GLM-07 — M4 대표 인카운터 에디터 셋업 `[코드 병렬 가능 / 검증 직렬]`

GLM-02의 설계가 끝나고 M2가 Play Mode에서 통과한 뒤 배정한다. 새 Editor 파일만 소유하게 하면 M3 UI와 코드상 병렬 작업이 가능하다.

**명령:**

> 기존 AI·예측·승패 경로를 재사용하는 대표 인카운터 에디터 메뉴를 구현하라. 유닛을 중복 생성하지 않는 멱등 셋업, 결정적인 배치·행동 순서, 예측-실측 로그를 제공하라. BattleManager와 AI 코어를 복제하거나 수정하지 말고 새 Editor 파일과 인계서만 변경하라.

### GLM-08 — M5 연결 검증 보조 도구 `[코드 병렬 가능 / 검증 직렬]`

GLM-03의 감사에서 실제 누락이 확인된 경우에만 배정한다. Outgame UI와 저장 파일 소유권을 작업서에 세밀하게 나눈다.

**명령:**

> 감사 문서에서 확인된 단일 연결 결함만 수정하라. 덱·스테이지·보상·저장·복귀의 기존 경로를 유지하고, 씬 직렬화 변경은 필요한 경우에만 별도 에디터 메뉴로 처리하라. 수정 범위를 넘는 UI 개편이나 새 메타 시스템은 금지한다.

### GLM-09 — M6 안정화 수정 `[최후순차]`

M2~M5의 Play Mode 검증이 모두 끝난 뒤에만 배정한다. 로그 정리와 밸런스 수치 조정은 같은 작업으로 묶지 않는다.

**명령:**

> 실패가 재현된 항목만 수정하라. 회귀 테스트 또는 수동 체크리스트를 먼저 추가하고, 그 테스트를 통과시키는 최소 코드만 변경하라. 대규모 리팩터링, 새 프레임워크, 씬·프리팹 일괄 변경은 금지한다.

## 병렬 실행 묶음

| 묶음 | 동시에 실행 가능한 작업 | 조건 |
|---|---|---|
| A | GLM-01, GLM-02, GLM-03, GLM-04 | 문서 파일이 서로 다름. Unity 실행 금지 |
| B | GLM-06, GLM-07 | M3 규칙과 M2 Play Mode 검증 완료, 파일 소유가 겹치지 않음 |
| C | GLM-08과 문서 감사 작업 | 수정 파일을 작업서에서 분리하고 Unity 검증은 한 번에 한 워크트리만 수행 |
| 직렬 | GLM-05 → GLM-06 → GLM-09 | 상태 API와 최종 회귀 결과에 의존 |
