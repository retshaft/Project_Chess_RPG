# Jev 기반 지속 개발 파이프라인

## 목표

Discord에 개발 요청을 등록하면 로컬 제어 프로세스가 요청을 작업 단위로 나누고, Jev의 저비용 판단으로 담당 모델과 다음 행동을 선택하며, 격리된 Git 워크트리에서 구현과 검증을 수행한다. 완성된 결과는 Codex 리뷰를 거쳐 통합 후보로 만들고 Discord에 보고한다. 프로세스가 종료되어도 로컬 상태에서 재개할 수 있어야 한다.

## 역할

| 구성요소 | 책임 |
|---|---|
| Discord | 요청 접수, 상태 확인, 중요 결정과 통합 승인 |
| 오케스트레이터 | 상태 전이, 잠금, 예산, 재시도, 실행 기록 |
| Jev | 준비도·담당 모델·실패 분류·재시도 가치 판단 |
| Codex | 요청 분해, 공통 설계, 변경 리뷰, 통합 판단 |
| ZCode / Antigravity | 범위가 고정된 구현 작업 |
| Git·컴파일·테스트 | 변경 범위와 성공 여부의 사실 판정 |

Jev의 출력 형식이 안전하다는 사실과 판단 내용이 정확하다는 사실을 구분한다. 파일 범위, Git 상태, 컴파일, 테스트 결과는 프로그램이 직접 확인한다.

## 상태 머신

```text
Requested
  -> Planning
  -> PlanReview            계획이 불명확하거나 공통 파일을 건드릴 때
  -> Ready                 실행 가능한 작업 계약 확정
  -> Routing               Jev가 작업과 담당 모델 선택
  -> Preparing             전용 브랜치·워크트리·작업 JSON 생성
  -> Running               담당 모델 실행
  -> Verifying             범위 검사·컴파일·관련 테스트
  -> Reviewing             Codex가 diff와 검증 근거 검토
  -> IntegrationReady      깨끗한 통합 워크트리에 반영 가능
  -> AwaitingApproval      main 반영 또는 기획 결정 대기
  -> Done
```

어느 단계에서든 `Attention`, `Paused`, `Rejected`로 이동할 수 있다. 모든 전이는 `.parallel` 아래 JSON에 원자적으로 기록한다. 실행 중 프로세스가 사라진 작업은 자동 성공 처리하지 않고 `Attention`으로 복구한다.

## 작업 계약

각 실행 작업은 다음 정보를 확정해야 한다.

- 고유 ID와 한 문장의 목표
- 현재 문제와 기대 동작
- 정확한 허용 파일 목록
- 완료 조건과 검증 방법
- 기준 커밋
- 선행 작업과 공통 API
- 허용 담당 모델
- 최대 실행 시간과 재시도 횟수

씬, 프리팹, 패키지, 공통 인터페이스, 저장 형식, 게임 규칙 수치가 포함되면 자동 통합 대상에서 제외한다.

## 판단 순서

1. 규칙 기반 검사로 실행 불가능한 작업을 제거한다.
2. Jev가 남은 작업의 우선순위, 담당 모델, 실행 또는 보류를 판단한다.
3. 신뢰도가 기준보다 낮으면 Codex 또는 사용자에게 올린다.
4. 구현 뒤 프로그램이 허용 파일, 브랜치, 컴파일과 테스트를 검사한다.
5. 실패가 발생하면 Jev가 구현 오류, 환경 오류, 범위 오류, 요구사항 오류로 분류한다.
6. 정책이 허용한 경우에만 한정된 횟수로 재시도한다.
7. 검증된 변경만 Codex 리뷰와 통합 후보 단계로 이동한다.

## 자동화 수준

### 자동 실행

- 명확한 작업 계약의 담당 모델 선택과 실행
- 허용 파일 검사
- 정적 검사와 지정된 테스트
- 동일 작업의 제한적 재시도
- 진행·완료·실패 Discord 알림

### Codex 검토 필요

- 자연어 요청의 작업 분해
- 여러 작업이 공유하는 인터페이스
- 실패 원인이 불명확한 경우
- 구현 diff 리뷰
- 충돌 해결과 통합 후보 작성

### 사용자 결정 필요

- 게임 규칙과 수치
- 시각적 취향 또는 기획 의도
- main 반영과 외부 push
- 대량 삭제나 데이터 변환
- 예산 상향

## Discord 명령

| 명령 | 기능 |
|---|---|
| `/dev-request` | 자연어 개발 요청 등록 |
| `/dev-status` | 현재 단계, 담당 모델, 최근 결과 확인 |
| `/dev-queue` | 대기 작업 확인 |
| `/dev-detail` | 작업 계약·판단·검증 근거 확인 |
| `/dev-start` | 새 작업 배정 허용 |
| `/dev-pause` | 새 작업 배정 중지 |
| `/dev-retry` | Attention 작업 재시도 승인 |
| `/dev-approve` | 계획 또는 통합 후보 승인 |
| `/dev-reject` | 작업 거부 및 사유 기록 |

## 구현 단계

1. 요청 접수와 파일 기반 상태 머신
2. Codex 구조화 계획 생성과 계획 검증
3. Jev 라우팅과 세 모델 실행기
4. 워크트리 자동 준비와 범위 검사
5. 검증 명령·Unity 실행권 연동
6. Codex diff 리뷰와 통합 후보 생성
7. Discord 승인·재시도·상세 조회
8. 재부팅 자동 시작, 복구, 비용·호출량 제한

각 단계는 앞 단계의 상태 파일을 입력으로 사용하며 Discord나 특정 모델 연결이 끊겨도 저장된 작업을 잃지 않는다.
